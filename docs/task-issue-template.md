# spotcode-sns で「タスク」として認識される GitHub Issue の書き方

## プロジェクトの達成アート（Web / Electron）

プロフィールの「プロジェクトの達成アート」で、リポジトリごとにチーム全員の担当Issueの完了を可視化できます。
設定 → 表示 → Open issues で公開リポジトリを選び、GitHubを連携したプロフィールを開いてください。
木・花・ルービックキューブの一面・パズルから絵を選べます。絵の選択はアカウント・リポジトリごとにこの端末に保存します。

1. プロジェクトを選択し、タスク名と担当者のGitHubユーザー名を入力します。
2. 「GitHubでIssueを作成」で開く画面で、内容とAssigneesを確認して作成します。指定したユーザーを割り当てられるかはGitHubの権限に従います。
3. 担当者が作業を終えたらGitHubで **Close as completed** を実行します。
4. アプリに戻ると進捗を再取得します。「進捗を更新」でも全員の最新の完了割合を反映します。未完了タスクのリンクからGitHubの詳細を開けます。

進捗は、現在担当者が設定されているIssue数に対する、担当者のいずれかが完了としてCloseしたIssue数です。
同じIssueは複数担当者がいても1件です。再オープンは進捗を戻し、Issueの追加・担当者変更により割合が変わります。
PR・担当者のいないIssue・「対応しない」でCloseしたIssue・spotcode非表示のIssueは集計対象外です。
担当者以外や自動処理がCloseしたIssueは完了に数えません。取得失敗時には不完全な集計を表示しません。
公開リポジトリに対応し、非公開リポジトリを選ぶと公開プロジェクトの選択を案内します。
ネイティブSwift画面にはこのアートはまだありません。

## Open issues の表示条件

Web・iOS・macOS版のプロフィールカード **Open issues** は、設定で表示対象に選んだリポジトリの
未完了Issueのうち、プロフィール本人が次のどちらかを満たすものを表示します。

- そのリポジトリにコミット履歴がある（現在の各ブランチの履歴を確認）。
- そのIssueを参照するPull Requestを本人が送っている（GitHubのIssueタイムラインで確認）。

Issueの作成者であることやOrganizationへの所属だけでは表示対象になりません。
PRだけで条件を満たす場合は、そのPRが参照するIssueに限ります。クローズ済み・未マージのPRも対象です。
公開Issueが基本で、非公開Issueは本人のプロフィールで追加権限と表示設定が有効な場合のみ取得します。
削除済みブランチからしか辿れないコミットは判定できません。Web版の取得結果は最大1時間キャッシュします。

issue 本文に `期限` / `Due` の行を書いておくと、
「あと N 日」「N 日超過」バッジと日時付きで表示されます。

## 最小テンプレート

Web / Electronでは **設定 → 表示 → Open issues →「Issueテンプレートをコピー」**、
またはプロフィールの達成アート内から、各テンプレートの「コピー」を押せます。
基本タスク・時刻付きタスク・提出課題・表示／非表示・GitHub常設用と、下記の期限表記6種類に対応しています。
日付や時刻のプレースホルダーは実際の期限に置き換えてください。担当者はGitHubのAssigneesで指定します。
GitHub常設用はIssue本文ではなく `.github/ISSUE_TEMPLATE/task.md` に保存します。

新しい issue を作るときに本文にこれをコピペしてください:

```markdown
**期限**: 2026-07-25
**spotcode表示**: する

## やること
- [ ] TODO 1
- [ ] TODO 2

## 詳細
自由に書いてください。
```

## Issueごとの表示設定

Issue本文の先頭付近に、次のどちらかを記載してください。

```markdown
**spotcode表示**: する
```

このIssueをプロフィールのOpen issuesへ表示します。

```markdown
**spotcode表示**: しない
```

このIssueはOpen issuesへ表示しません。`非表示`、`OFF`、`false`、`no` も
`しない` と同じ扱いです。大文字・小文字は問いません。

| 記述 | 結果 |
| --- | --- |
| `spotcode表示: する` | 表示 |
| `**spotcode表示**: する` | 表示 |
| `**spotcode表示:** しない` | 非表示 |
| `spotcode表示: OFF` | 非表示 |
| 記述なし | 表示（既存Issueとの互換性） |

リポジトリ側で一時的に隠したい場合は、`spotcode非表示` または
`spotcode-hidden` ラベルでも非表示にできます。本文の設定とラベルの
どちらか一方が非表示なら、そのIssueは表示されません。

## 非公開リポジトリの課題Issue

`hrmcngs/.github-private` のような非公開リポジトリは、設定 → 表示 → Open issues の
「非公開Issueを表示する（GitHub再認証）」を有効にした本人のプロフィール画面だけに表示されます。
GitHubの仕様上、この機能は再認証時に `repo` 権限への同意が必要です。他ユーザーや未ログインの画面には表示されません。

学校課題では次の書式も期限として認識します。年を省略した場合は現在年として扱います。

```markdown
**提出期限**: 2026-09-02 08:25
**spotcode表示**: する
```

これだけで:

- プロフィールに **`@handle` が Open にしている task 一覧** としてタイトルが出る
- 期限日が **`2026-07-25 · あと 10 日`** のようなバッジになる
- 過ぎたら赤 (`N 日超過`)、3 日以内なら黄色、それ以外はグレー
- 早い順に並ぶので、上から片付ければ間に合う

## 期限の書き方

以下のどれでも認識します (大文字小文字問わず、`:` の後は空白 OK):

| 例 | 認識される |
| --- | --- |
| `期限: 2026-07-25` | ✅ |
| `**期限**: 2026-07-25` | ✅ |
| `Due: 2026-07-25` | ✅ |
| `Deadline: 2026-07-25T15:00` | ✅ (時刻付き) |
| `締切: 2026年7月25日` | ✅ |
| `by 2026/07/25 15:00` | ✅ |

**時刻を書かない**場合は「その日の 23:59」扱いになるので、`2026-07-25` と
書いたら 26 日の午前 0 時に「1 日超過」になります (日付だけ書いた日の
うちは overdue にならない挙動)。

**複数書いた場合**は最初にマッチしたものが採用されます。

## GitHub 側にテンプレートを常設したい場合

`.github/ISSUE_TEMPLATE/task.md` を repo に置いておくと、
「New issue」画面でこのテンプレートが選択肢に出てきます。
spotcode-sns 本体には既に置いてあるので、そちらをコピーして使えます。

## こう見えます (例)

プロフィール上の Open issues カードで:

```
Open issues  3   公開リポの未クローズ issue (task)

  ┃ バグ: 通知がリロードしないと来ない
  ┃   hrmcngs/spotcode-sns   [bug]   2026-07-15 · 3 日超過
  ┃   通知タブを開いたときに 60 秒ポーラーが …

  ▎ タスク: privacy-mode で bio も masking する
  ▎   hrmcngs/spotcode-sns   [feature]   2026-07-18 · あと 2 日
  ▎   /settings → プライバシー タブに add-on として …

    Refactor: router を SPA から MPA 対応にする
        hrmcngs/spotcode-sns   2026-08-30 · あと 44 日
        後回しでもいい調整。時間があるときに手を付ける
```

赤い縦線 (┃) = overdue、黄色い縦線 (▎) = 3 日以内 (soon)、線なし = later。
これで見た瞬間「この人このひまでにこれやらないとだよー」が分かります。
